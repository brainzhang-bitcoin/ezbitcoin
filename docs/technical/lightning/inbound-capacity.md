# 真实工程困境：通道入站容量谜题 (Inbound Capacity)

初次体验闪电网络的新手，通常会经历这样一条链路：
1. 向闪电节点的链上地址充入小额比特币；
2. 连接到一个公共公网节点，发起 `openchannel`，将资金注入通道；
3. 通过闪电网络秒级向外支付了一笔测试款项。

一切顺风顺水。然而，当他兴致勃勃地准备生成一个收款发票（Invoice），让朋友向他付款时，却往往会迎头撞上闪电网络最令人困惑的工程墙：
> **“为什么别人向我付款总是报错，提示找不到路由或通道容量不足？我明明刚充值并打开了一个大容量通道！”**

本章将为您揭示闪电网络中关于流动性的核心概念——**本地余额、远程余额与入站容量（Inbound Capacity）**。

---

## 1. 沙漏模型：本地余额与远程余额

当我们使用 `lncli listchannels` 查看一个刚建立的通道时，核心字段如下：

```json
{
    "active": true,
    "remote_pubkey": "03a8334aba5660e241468e2f0deb2526bfd50d0e3fe808d882913e39094dc1a028",
    "channel_point": "b0a0afb65ac08f453b26fa03a40215be653b6d173510d366321019ab8248ea3b:0",
    "capacity": "1000000",
    "local_balance": "995000",
    "remote_balance": "0"
}
```

请密切注意 `local_balance`（本地余额）与 `remote_balance`（远程余额）的区别：
* **通道容量 (Capacity)**：通道在链上锁定的比特币总额。在不关闭通道或执行拼接（Splicing）的情况下，这个总量是不可改变的。
* **本地余额 (Local Balance / 出站容量 Outbound Capacity)**：当前属于你所有的金额。**决定了你能够向外支付的资金上限**。
* **远程余额 (Remote Balance / 入站容量 Inbound Capacity)**：当前属于通道对端所有的金额。**决定了你能够从外部接收付款的资金上限**。

![闪电通道沙漏模型](../../images/blog_brain-zhang_brain-zhang.github.io_source_20191106_bg0.png)

### 形象的沙漏隐喻
你可以把支付通道想象成一个密封的沙漏：
* 沙子的总量是固定的（通道容量）；
* 当你对外付款时，你这端的沙子（本地余额）会流入对方那一侧（远程余额）；
* 当别人向你付款时，对端一侧的沙子流入你这一侧。

![通道余额流动](../../images/blog_brain-zhang_brain-zhang.github.io_source_20191106_bg2.png)

**困境的核心**：当你单方面出资开辟一条通道时，所有的资金都处于你这一侧（`local_balance` 占满，而 `remote_balance = 0`）。
**由于对方一侧空空如也，根本没有任何沙子可以推向你这一侧，因此你无法接收任何款项！**

---

## 2. 商家与个人用户的现实流动性痛点

这一看似简单的工程机制，对闪电网络的实际运营提出了严峻挑战：

1. **普通新手用户**：初次打开钱包，如果只想收款而从未向外花过钱，他必须先说服别人或者依靠服务商为他开通一条注入了远程资金的通道。
2. **闪电网络商家**：比如一家在线咖啡店，每天都在源源不断地接收顾客的闪电支付。随着顾客付款，商家的 `remote_balance` 迅速被耗尽，全转移成了 `local_balance`。一旦入站容量归零，新顾客便再也无法下单！

---

## 3. 获取入站容量的主流方案

为了给通道注入宝贵的“入站容量”，生态中演化出了几种经典解决方案：

### 1. 先花钱后收款 (Spend to Receive)
最原始的办法：先通过闪电网络买杯咖啡、购买 VPN 服务或向交易所充值，将部分本地余额推到对端，从而腾出接收额度。

### 2. 双向注资通道 (Dual-Funded Channels)
在开启通道时，通过协议协商，让对端也拿出一部分资金共同注资（如 Lightning 规范支持的双向注资）。

### 3. 流动性服务提供商 (LSP - Lightning Service Providers)
向专业节点营运商购买流动性服务（例如 Bitrefill 的 Thor、Lightning Labs 的通道租用等）。你支付小额服务费，LSP 节点主动向你发起一条拥有充沛远程余额的通道。

### 4. 潜艇互换 (Submarine Swaps)
这是目前最优雅且去中心化的终极解决方案：**无需关闭通道，通过原子跨层互换，将通道内的本地余额抽回链上，瞬间恢复通道的入站收款能力！**

关于潜艇互换与 Lightning Labs Loop 服务的技术细节，请阅读下一节：[容量破局之道：Loop 潜艇互换机制](submarine-swaps-loop.md)。
